# 长文档处理与来源位置

[返回首页](../README.md) · [实现详解](implementation.md#module-retrieval)

## 当前生产检索：BM25

生产入口使用 [evidence_store.py](../src/adra/evidence_store.py)，从工具实际返回的全文中重新检索，不在第一次截断结果上继续截断。返回全文不等于网站所有内容均已抓取。

- 1200 字符窗口、900 字符步长；英文/API 标识符和中文双字保留出现次数。
- 文档长度按词项数量计算，查询词去重；`k1=1.2`、`b=0.75`。
- 正 IDF：`log(1 + (N - df + 0.5) / (df + 0.5))`。
- 单词贡献：`idf * tf * (k1 + 1) / (tf + k1 * (1 - b + b * dl / avgdl))`。
- 每个查询默认保留四个正分候选，跨查询轮流分配字符预算，合并重叠片段。
- 研究/写作交接默认 12000 字符，主题评估 8000，声明核验和 compact 反思 6000；这些是选段预算，不是模型总 Token 上限。

写作 `handoff_evidence()` 还汇合历史完整片段，按查询排序并检查来源版本和偏移。所有字符预算均可能淘汰有用证据；BM25 分数不表示语义支持概率。详细来源与算法差异见 [BM25 定义](review-followup.md)。

片段使用零起点、左闭右开区间：`raw[start:end] == text`。新字符按相同来源哈希的历史区间并集计量，重复边界不算新增信息；原文存储仍没有全局内存上限。

## 历史实现：lexical_passages_v1

以下只用于理解历史实验，不是当前生产检索参数。历史代码与测试不能用来说明新版本的算法收益。

旧实现对搜索摘要和正文直接取前 6000 字符，新实现保留工具返回全文，再选择有界片段。
原始长度指**搜索/提取工具实际返回的字符串长度**，并不表示原始网站全部内容已被抓取。

### 选择算法

- 短于等于 6000 字符的内容原样保留，包括首尾空白。
- 长文按空行划分段落，支持 LF/CRLF。超长段按 1000 字符切块，相邻候选重叠 100 字符。
- 英文按字母、数字、下划线提取词项；连续中文生成双字词项。
- 每个关联子任务使用描述与查询作为关注点；无计划时使用研究问题。
- 得分为片段与关注点的唯一词项交集数除以关注点词项数。
- 优先为每个关注点选择一个有匹配的片段，再按分数填充剩余空间。预算不足时不能保证所有任务获分配。
- 最终片段按原文顺序排列，不重叠，拼接及分隔符总计不超过 6000 字符。
- 没有任何匹配时按原文顺序选择；相同输入与关注点产生相同结果。

它不是 embedding 检索或语义验证。同义表达、跨段关系、分词边界和关键词堆积仍可能影响结果。
100 字符重叠减少切断短关键词的风险，并不保证所有跨块语义得到保留。

### 元数据

每条 Evidence 增加：

| 字段 | 定义 |
| --- | --- |
| original_length | 原始工具文本的 Python 字符数，不是字节或 Token 数 |
| selected_length | 提供给模型的拼接内容字符数，含分隔符 |
| truncated | 至少有部分原始字符未包含在选中区间中 |
| raw_sha256 | 原始文本 UTF-8 编码的 SHA-256 |
| raw_kind | search 或 read，定位对应原始工具文本 |
| selection_method | lexical_passages_v1 |
| selection_focus | 本次选择所用的任务 ID、描述与查询 |
| passages | 文本、start/end、paragraph_index、score、matched_task_ids |

`start/end` 使用零起点、左闭右开字符区间：

```python
raw = result['raw_documents'][evidence['id']][evidence['raw_kind']]
for passage in evidence['passages']:
    assert raw[passage['start']:passage['end']] == passage['text']
```

长文片段的 paragraph_index 为零起点段落编号。短文整体保留时使用 null，表示整个文档，
不将它错误标成单个段落。片段可能不连续，Writer 提示词要求尊重位置和省略信息。

### 原文与轨迹

`run.json.raw_documents` 每个证据 ID 保存一次搜索摘要和一次成功提取正文。
图状态的模型视图不包含原文存储；轨迹只保存当时选中的片段和元数据。
相同来源后来关联其他任务时，根据所有关联任务从已保存原文重新选择，不发起重复阅读。
历史轨迹保持原先选择，不会被后续选段修改。

没有为原始存储添加全局字符/内存上限：很大工具返回值会增加内存和 run.json 体积。
6000 是每来源展示文本上限，不是总模型输入上限；位置元数据和历史状态同样消耗 Token。
当前没有强制总 Token 预算。元数据中的截断状态也不用于判定语义覆盖。

### 验收

离线示例：`data/passages/plan.json` 和 `data/passages/snapshot.json`。
回归测试包括后半段关键信息、中文、长单段、短文原样保存、无匹配回退、共享任务重新选段、
历史不可变及保存后的原文区间复核。相关信息进入报告只验证提取机制，不代表研究质量提升。
