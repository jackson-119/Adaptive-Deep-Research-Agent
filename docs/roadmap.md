# 后续优化与验收

[返回项目首页](../README.md)


以下为待实施事项，不代表功能已经实现。先修复评估可靠性与研究停滞，再扩大对照实验。

| 优先级 | 优化部分 | 当前问题 | 拟实施方向 | 验收方式 |
| --- | --- | --- | --- | --- |
| P0 | [写作到评估的证据交接](implementation.md#module-evaluation) | 独立检索可能漏掉写作已使用的支持段落 | 保存逐声明证据位置；将相关写作片段与独立检索结果合并，继续验证哈希和出处 | 固定语料回归中，路由与部分更新原文对相应核验可见；保持总输入预算 |
| P0 | [声明核验一致性](implementation.md#module-verification) | 检索非空但不充分时，没有补充原写作证据 | 区分证据选择不足和模型判定；使用统一的可追溯证据输入 | 人工复核同一事实在覆盖评估和声明核验中的差异；不以强制同分替代正确性 |
| P1 | [检索停滞与停止决策](implementation.md#module-controller) | 新增字符不等于补齐缺口，近似查询反复消耗步骤 | 记录缺口、相近查询与命中段落变化；停滞时切换外部搜索或带局限结束 | 比较后半程无效动作、Token、报告覆盖与支持率，防止仅靠提前停止降低成本 |
| P1 | [反思标准约束](implementation.md#module-reflection) | 模型生成的 missing_facts 可能扩张验收要求 | 建立缺口与原始验收项的对应关系；将额外细节作为可选建议 | 固定样例检查是否追加原问题未要求的字符串值、校验机制等条件 |
| P1 | [决策上下文成本](implementation.md#module-controller) | Event 的主要 Token 消耗可能来自多轮决策，而非反思本身 | 去掉重复正文，按待解决问题选择上下文，保留必要历史与出处 | 在相同模型和预算下比较 decision 阶段 Token、失败率和质量；避免压缩后丢证据 |
| P2 | [真实任务对照实验](implementation.md#module-evaluation) | 目前单任务、单次样本不足以证明收益 | 修复后先重评同一批旧报告，再运行 3～5 个任务、每组至少 3 次 | 保持模型、计划、预算和评分版本一致；同时报告未完成比例、成本与人工复核结果 |
| P2 | [检索与运行扩展](implementation.md#module-retrieval) | BM25 跨语言召回有限，长任务缺少中断恢复 | 根据多任务错误分布决定是否增加混合检索、重排与持久化恢复 | 通过单独消融验证新增模块的收益和额外成本，不预设必须增加复杂度 |

当前阶段的目标是让研究结果可追溯、评分可信、成本可比较。只有在评估完整且标准一致的多任务重复实验中，才能进一步判断 Event Reflection 是否优于 Baseline。

SFT/GRPO、训练数据和 Ascend 本地推理不在当前研究 Agent 与评测验收范围。
