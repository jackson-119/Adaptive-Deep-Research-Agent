# 自动任务分解

自动规划是研究循环前的独立步骤。使用 `--strategy static|adaptive --auto-plan`，由当前
`ADRA_MODEL` 输出 Plan 结构，再复用现有执行器。它不在研究过程中修改任务图。

## 校验与预算

除 Plan 的依赖 DAG、唯一 ID、全局唯一查询等校验外，还检查：

- 计划 query 与输入问题一致（去除首尾空白）。
- 最多 `min(6, min(tool_calls, steps) // 2)` 个任务。
- `任务数 + sum(target_sources)` 不超过工具和步骤预算中较小者。

预算约束采用每任务一次搜索、每目标来源一次阅读的估计，不保证搜索成功或任务全部完成。
计划生成的模型调用不消耗工具次数，但计入模型调用次数和 Token 用量。尚无总 Token 硬预算。

## 有限修正

校验失败后，最多再请求一次模型修正。修正提示包含通用规则，不回传原始错误或无效模型响应。
两次失败则停止；网络等非 ValueError 异常直接失败，无自动重试。单次模型请求沿用超时配置。

自动规划不支持离线快照：模型生成的查询不一定存在于精确匹配快照中。
需要固定快照实验时，先保存并复用人工或生成的计划，再准备对应查询的快照。

## 产物与成本记录

- `plan.json`：校验通过的计划，可使用 `--plan` 重用。
- `run.json.plan_source`：generated、file 或 null。
- `run.json.plan_generation`：校验尝试、结果及规划延迟。
- `run.json.model_call_records`：每次模型调用的阶段（planning/decision/writing）、状态、
  已知 Token 和延迟。结构合法但问题/预算不匹配的调用，其调用状态可能为 ok，
  而对应 plan_generation 尝试为 invalid_plan；二者分别表示解析与业务校验结果。
- `failure.json`：自动规划或后续执行失败时的异常类型、已知模型用量及规划记录；若有合法计划也会保存。

失败记录不是检查点，不包含完整的失败研究状态，当前不支持断点恢复。
总用量包含无效计划的调用；若供应商未返回用量，完整性标记为 false，已知总量只是下界。
总延迟包含自动规划及研究执行，不包含客户端模型初始化和文件保存。

## 验证边界

测试使用模拟模型覆盖成功规划、错误问题、循环依赖、超预算、重复查询、二次修正失败、
供应商异常、缺失用量、CLI 参数约束和产物保存。在线 CLI 集成测试需要 live 可选依赖。
用户已在云服务器使用 DeepSeek + Tavily 完成在线功能验证，包括计划生成、校验与修正。
这不代表计划质量或算法收益已获验证；本地回归仍使用模拟响应。
