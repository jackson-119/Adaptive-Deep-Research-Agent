## 域名约束设计

`--allowed-domain` 可重复传入，默认不限制。采用**精确主机名匹配**，不接受 URL、路径、
通配符或端口。主机名转为小写和 IDNA，允许一个 DNS 末尾点。
子域名必须显式列出；URL 中的路径、查询、账号信息不能用来匹配域名。
URL 必须使用 HTTP(S)，不允许嵌入凭据、反斜杠或控制字符。

验证层次：

1. Tavily Search 传递 `include_domains` 和 `include_domains_mode=restrict`。
2. 执行器逐条校验收到的搜索结果（离线快照也适用），拒绝项不进入证据。
3. READ 校验请求主机名；受限 Tavily Extract 必须返回允许域名的来源 URL，否则拒绝正文。
4. Writer 接收证据前复核来源，再对报告引用的证据编号与 URL 做检查。

被拒绝的搜索结果增加轨迹 `rejected_sources`，不算工具请求失败。
阅读拒绝记录 `SourceDomainError`；已经发生的工具请求仍消耗预算。
无来源时不放宽规则。`run.json.config.allowed_domains` 与每步状态保存有效约束。

域名白名单由调用者提供，程序不判断该域名是否真为某组织官方。
返回 URL 是提取器提供的来源元数据，本地不会独立抓取或审计其隐藏重定向链。
规则保护结构化证据与引用，不保证模型生成段落中没有第三方链接，更不保证事实正确。

接口依据：[Tavily Search](https://docs.tavily.com/documentation/api-reference/endpoint/search)、
[Tavily Extract](https://docs.tavily.com/documentation/api-reference/endpoint/extract)。

## 保留修改前样本

本轮没有覆盖既有 outputs，也未将合成示例当成云端运行样本。
云端真实运行目录未随反馈同步到本地，因此仍需在云服务器保留它的完整副本：

- 完整运行目录：report.md、run.json、trajectory.jsonl、plan.json（若存在）。
- 当时的代码提交、未提交补丁（若有）、uv.lock、模型名称、运行命令和预算。
- 搜索和阅读原始返回若未记录，则无法事后精确重建工具快照；不要把摘要称为原始正文。
- 不保存真实 API Key。含密钥的 shell 命令应先移除密钥再归档。

新运行增加 `provenance`，记录 Git commit、dirty 状态、Python 和依赖版本。
若 dirty 为 true，提交号不能单独标识当前代码，归档时仍应保留代码或补丁。
这些元数据不会自动修复旧运行中缺失的版本信息。

## 同题复测

沿用云端原模型、问题和预算，新增官方域名约束。检查：

- 所有 evidence URL 的 hostname 在配置白名单内；报告引用均对应这些证据。
- 轨迹中可以追踪被拒绝来源数；没有默认放宽搜索。
- 保存新目录，比较实际调用、Token、延迟及人工审阅报告质量。

离线测试覆盖伪装域名、大小写、末尾点、IDNA、混合来源、全拒绝、请求参数、
提取返回越域/缺失 URL、引用校验及 CLI。它们证明过滤规则，不证明研究质量提高。
后续需不同问题及固定快照对照；当前仍不开展 NPU/GRPO 训练。

实现细节与人工复核入口见 [语义覆盖](semantic-coverage.md)。
